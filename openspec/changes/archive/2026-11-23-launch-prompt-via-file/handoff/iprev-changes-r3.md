The rollback was redesigned around it:
1. Structural rollback: a `LaunchRollback` drop guard armed right after `reserve_session_pty`, disarmed only after the PTY write. Every `?`/return Err/panic in between rolls back (registry lookup, lock errors, write_all/flush included). Gone path disarms (kill path already cleaned, prompt not yet consumed). Requirement renamed "A failed launch leaves no trace and keeps the prompt" and its text says "any error after the PTY reservation". Design D3 rewritten.
2. Obsidian: rollback inserts the pty id into `PtyManager.aborted_launches` before killing the shell; the EOF branch takes it and skips `finalize_session_obsidian` (claim not spent). Scenario "Aborted launch writes nothing to the vault" incl. a later successful launch still finalizing.

5. One-newline scenario scoped to "no startup prelude"; multi-line prelude noted as pre-existing in Risks.
