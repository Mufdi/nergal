### Band C — robustness

**6. `prune-session-scoped-state`** (standard, write design.md) — tier M, risk low.
Per-session Jotai `Record<string, …>` maps are never pruned when a session closes permanently. `src/stores/sessionTabs.ts:176-184` (`finalizeSessionCloseAction`, the only path after the 5s soft-close window) calls only `terminalService.destroy(sessionId)` + removes from `pendingSessionClosesAtom`; it touches none of the ~55 session-keyed maps (e.g. `activity.ts:7`; `git.ts:37,56,73,93,128,141,155,164,173,191,200,205,220,225`; `clickup.ts:101,300,304`; `linear.ts:256,260`; `plan.ts:9,33,53,82,104`; `rightPanel.ts:85,90,111,326,329`; `quake.ts:28,30,31`; `scratchpad.ts:41,46,51,76`). In a long-lived app that spawns many worktree sessions, every session ever opened keeps a footprint for the process lifetime. Fix: a shared `pruneSessionAtom(sessionId)` wired into `finalizeSessionCloseAction` (and any other permanent-delete path), clearing each map's key; consider a registry/lint pattern so new session-keyed atoms auto-register (the manual list rots). Exclude derived read atoms (e.g. `workspace.ts:116`). spec_target: MODIFIED `session-directory` or `tab-system` — session-scoped in-memory state is reclaimed on permanent close.

**7. `resilient-config-load`** (quick-fix) — tier S, risk medium.
`src-tauri/src/config.rs:432-437` (`Config::load`) — `serde_json::from_str(&contents).unwrap_or_default()` silently discards any deserialize error and substitutes `Self::default()`. The next `config.save()` (triggered by almost any settings change) then overwrites the corrupt file with defaults, permanently destroying the user's prior config (agent overrides, keymap, themes, tracker tuning). Fix: on parse error, log it and back up the unparseable file (e.g. `config.json.corrupt`) before falling back to defaults. spec_target: New capability `config-persistence` — a malformed config is preserved (backed up), never silently overwritten.

**8. `fix-pty-double-spawn`** (standard, write design.md) — tier M, risk medium.
`src-tauri/src/pty.rs:526-533` checks `session_ptys.get(&session_id)` under a lock dropped before `spawn_pty` runs unlocked; `session_ptys.insert(...)` happens after (~558-562). Two concurrent `start_claude_session` for the same id both pass the check, both spawn, the second `insert` clobbers the first — orphaning a PTY that `kill_session_pty` can never find. `spawn_aux_shell` (~861-867) already reserves the key under one lock hold with a comment naming this hazard. Fix: reserve the `session_ptys[session_id]` slot under a single lock hold before `spawn_pty`, mirroring `spawn_aux_shell`, with rollback on spawn failure. Pairs with the Band-A `reap-pty-child-zombies` change (an orphaned PTY is also unreaped). spec_target: MODIFIED `session-directory` — session PTY creation is idempotent per session id.

**9. `release-db-lock-during-io`** (standard, write design.md) — tier M, risk medium.
Several async Tauri commands hold the global `Mutex<Database>` guard across blocking git/network work: `delete_session` (`commands.rs:986-1046`, runs `MocBuilder::build` git diff + `worktree::remove_worktree` shelling out), `git_ship` (`commands.rs:2872-2918`), `create_pr` (`commands.rs:2586-2619`, network push + `gh pr create`). While any runs (seconds on slow disk/net), every other command touching the DB mutex blocks, freezing the data layer. Fix: extract needed fields from the DB, drop the guard, then run the git/network work without holding `db` (wrap blocking parts in `spawn_blocking`). spec_target: New capability `db-lock-discipline` — long-running git/network work is not performed while holding the database mutex.

**10. `jsonl-partial-line-buffering`** (quick-fix) — tier S, risk medium.
`src-tauri/src/agents/pi/jsonl_tail.rs:139-156` and the identical pattern in `src-tauri/src/agents/codex/rollout_tail.rs:230-253` — both `read_appended` read to EOF, iterate `buf.lines()`, and set `new_offset = offset + n` regardless of whether the read ended mid-line. A `notify::Modify` firing while the CLI is mid-write leaves a partial final line that fails to parse and is discarded, and the offset advances past it, so the completed record next read also starts mid-JSON and is lost — silent gaps in Modified Files/status panels for both adapters. Fix: buffer bytes after the last `\n` across reads; advance the offset only by the length of fully-terminated lines consumed. spec_target: MODIFIED `agent-adapter` (or the pi/codex adapter specs) — tail readers never drop a record split across reads.

**11. `clickup-writeback-echo-ordering`** (quick-fix) — tier S, risk medium.
`src-tauri/src/clickup/mod.rs:512-545` (`clickup_set_task_status`) and the same shape in `clickup_update_task`/`clickup_set_custom_field`/`clickup/closure.rs` — `registry.record(...)` runs only AFTER `client.*(...).await` succeeds. Linear's equivalent (`linear/mod.rs:953-1100`, `linear/writeback.rs:87`) records BEFORE the API call (provisional) to close the window where a concurrent poll lands between the write and the record, misclassifying the server value as a real change instead of an own-echo (spurious self-notification on the "assign to me" flow). Fix: move each `registry.record(...)` before its `client.*` await across the four ClickUp write commands, mirroring Linear. spec_target: MODIFIED `clickup-writeback` — own-echo suppression is recorded provisionally before the API call.

**12. `cross-session-delivery-confirmation`** (standard, write design.md) — tier M, risk medium.
`src-tauri/src/mcp/delivery.rs:46-67` — `AppBridge::wake_idle` returns `Ok(())` right after the paste; the actual Enter/submit runs in a detached `tauri::async_runtime::spawn` 250ms later with `let _ = crate::pty::submit_to_session(...)` (error discarded). `drain_idle` (~141-155) treats the `Ok` as "delivered" and marks the message `agent_consumed_at` in the DB before the deferred submit runs. If the target PTY closes/switches within that window, the submit fails silently, the text sits unsent, but the message is already consumed — never retried — while the sender saw "delivered." Fix: have `wake_idle` await the submit (or return a future) so consumption is recorded only after submit succeeds; leave unconsumed on failure so the next drain retries. spec_target: MODIFIED `cross-session-messaging` — a message is marked consumed only after its submit to the target is confirmed.

**13. `unique-merge-worktree-path`** (quick-fix) — tier S, risk medium.
